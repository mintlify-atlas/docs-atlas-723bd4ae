CVR-MATE exposes a REST API that covers every platform feature — the web app itself is built entirely on top of this API. If you are integrating CVR-MATE programmatically or building tooling on top of it, you use the same API the frontend uses.

<Note>
  All `/api/*` routes require an authenticated session cookie. See [Authentication](/api-reference/authentication) for how to obtain and include a session.
</Note>

## Base URL

All endpoints are relative to your CVR-MATE deployment:

```
https://your-domain.com/api
```

For local development the base URL is `http://localhost:3000/api`.

## Response format

All endpoints return JSON. Successful responses include a top-level data object or array. The exact shape is documented per endpoint.

## Error responses

CVR-MATE uses standard HTTP status codes for all errors.

| Status | Meaning |
|--------|---------|
| `401 Unauthorized` | No active session, or session has expired. Sign in again. |
| `403 Forbidden` | Authenticated but your plan or role does not permit this action. |
| `404 Not Found` | The requested resource does not exist. |
| `409 Conflict` | The request conflicts with existing data (e.g., duplicate entry). |
| `429 Too Many Requests` | Rate limit exceeded. AI endpoints are subject to per-plan monthly quotas. |
| `500 Internal Server Error` | An unexpected server-side error occurred. |

All error responses use the same body shape:

```json
{ "error": "Error message here" }
```

## Rate limiting

Standard API endpoints do not impose hard per-request rate limits beyond what your infrastructure enforces. AI endpoints (`/api/ai/*`) are subject to **per-plan monthly usage quotas**. When you exceed your quota, the endpoint returns `429 Too Many Requests` with an explanatory error message.
