---
title: "Saved companies API: bookmark and manage leads"
description: "Endpoints to save, list, update, and remove CVR companies from your personal or team watchlist. Supports notes, tags, and organisation-scoped bookmarks."
---

The saved companies API lets you bookmark Danish CVR companies as leads or prospects, attaching personal notes and tags to each entry. Saved companies are stored in your CVR-MATE account and can optionally be scoped to a team organisation so that all members see the same watchlist. All endpoints require an authenticated session.

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/cvr/saved` | List saved companies for the current user and active organisation. |
| `POST` | `/api/cvr/saved` | Save a new company bookmark. |
| `PATCH` | `/api/cvr/saved` | Update the note or tags on an existing bookmark. |
| `DELETE` | `/api/cvr/saved` | Remove a saved company bookmark. |

---

## POST /api/cvr/saved — Save a company

Creates a new bookmark for the specified CVR company. If the company does not yet exist in the CVR-MATE database it is inserted automatically. If the company has already been saved in the same scope (personal or organisation), the endpoint returns `200` with `alreadyExists: true` rather than creating a duplicate.

<Note>
  Plan limits apply to the total number of saved companies. Exceeding your plan's limit returns `403` with `"upgrade": true`.
</Note>

### Request

```
POST /api/cvr/saved
Content-Type: application/json
```

### Body parameters

<ParamField body="vat" type="string" required>
  The CVR/VAT number of the company to bookmark.
</ParamField>

<ParamField body="name" type="string" required>
  Company name. Used as a fallback display name if `rawData` is not provided or does not contain `life.name`.
</ParamField>

<ParamField body="rawData" type="object">
  Full `CvrCompany` JSON object as returned by `/api/cvr/company`. When provided, CVR-MATE extracts and denormalises key fields (city, zipcode, address, industry, company type, status, founded, employees) into the cached company record for fast filtering and display.
</ParamField>

<ParamField body="note" type="string">
  A personal free-text note to attach to this bookmark (e.g. `"Spoke to CEO at Nordic SaaS conf"`). Whitespace is trimmed; blank strings are stored as `null`.
</ParamField>

### Response

```json
{ "saved": true }
```

On duplicate:

```json
{ "saved": true, "alreadyExists": true }
```

A `201 Created` status is returned for new bookmarks; `200` is returned when the company was already saved.

## PATCH /api/cvr/saved — Update note or tags

Updates the note and/or tags on an existing saved company. You must supply at least one of `note` or `tags`.

<Note>
  Tags are normalised: each tag is trimmed, truncated to 30 characters, and deduplicated. A maximum of 10 tags per bookmark is enforced.
</Note>

### Request

```
PATCH /api/cvr/saved
Content-Type: application/json
```

### Body parameters

<ParamField body="cvr" type="string" required>
  The CVR number identifying the saved company to update.
</ParamField>

<ParamField body="note" type="string">
  Updated note text. Pass an empty string or `null` to clear the note.
</ParamField>

<ParamField body="tags" type="string[]">
  Replacement tags array (e.g. `["hot lead", "partner"]`). This replaces the existing tags entirely — pass an empty array to clear all tags.
</ParamField>

### Response

```json
{ "updated": true }
```

## DELETE /api/cvr/saved — Remove a saved company

Removes the bookmark for the specified CVR number from the authenticated user's saved list.

### Request

```
DELETE /api/cvr/saved?cvr=12345678
```

### Query parameters

<ParamField query="cvr" type="string" required>
  The CVR number of the company to remove from saved companies.
</ParamField>

### Response

```json
{ "removed": true }
```

<Warning>
  Deletion is immediate and permanent. The underlying cached company record is not deleted — only the bookmark is removed.
</Warning>

---

## Organisation scoping

When a user has an active organisation, `POST /api/cvr/saved` automatically associates the bookmark with that organisation. Organisation-scoped bookmarks are visible to all members of the organisation in their `GET /api/cvr/saved` responses.

Personal bookmarks (no active organisation) are private to the user who created them. Bookmarks are matched in the same scope: a company saved personally and again under an organisation creates two separate records.

## Saved searches

You can also persist entire search filter sets for quick re-use. The saved searches API is available at `/api/saved-searches`:

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/saved-searches` | List saved search filters for the current user. |
| `POST` | `/api/saved-searches` | Save a new named filter set. |

Each saved search stores a `name` and a `filters` JSON object matching the parameters accepted by `/api/cvr/search`. Saved searches can also be scoped to an organisation.

## Example

```bash
# Save a company
curl -X POST https://your-domain.com/api/cvr/saved \
  -H "Content-Type: application/json" \
  -b cookies.txt \
  -d '{"vat":"12345678","name":"ACME ApS","note":"Strong prospect","rawData":{...}}'

# List saved companies
curl https://your-domain.com/api/cvr/saved \
  -b cookies.txt

# Update note and tags
curl -X PATCH https://your-domain.com/api/cvr/saved \
  -H "Content-Type: application/json" \
  -b cookies.txt \
  -d '{"cvr":"12345678","note":"Followed up 2026-04-28","tags":["saas","growth","warm"]}'

# Remove a bookmark
curl -X DELETE "https://your-domain.com/api/cvr/saved?cvr=12345678" \
  -b cookies.txt
```
