---
title: "GET /api/cvr/company — Fetch company by VAT"
description: "GET /api/cvr/company — fetch a full CVR company profile by VAT number, including participants, financials, and employment history. Results are Redis-cached."
---

The company endpoint returns the complete CVR record for a single Danish company identified by its 8-digit VAT/CVR number. Data is sourced from the CVR API and cached in Redis; subsequent requests for the same VAT are served from cache until the TTL expires. The response is wrapped in a `company` key and includes the full `CvrCompany` object — address, company form, status, contact details, industry classification, financial summaries, employment history, and director/owner participants.

## Request

```
GET /api/cvr/company
```

### Query parameters

<ParamField query="vat" type="string" required>
  The 8-digit Danish CVR/VAT registration number (e.g. `12345678`). Non-numeric values or numbers that are not exactly 8 digits are rejected with a `400` error.
</ParamField>

### Error responses

| Status | Meaning |
|--------|---------|
| `400`  | Missing or malformed `vat` parameter (must be exactly 8 digits). |
| `404`  | Company not found in the CVR registry. |
| `500`  | Upstream CVR API failure. |

### Caching

Company data is cached in Redis using a configurable TTL (see `CACHE_TTL.company` in `lib/cache.ts`). A background cron worker (`/api/cron/person-changes`) refreshes data for followed participants. You can force a fresh fetch by calling the endpoint after the TTL has expired, or by using the internal `getCompanyByVatFresh` utility in server-side code.

<Note>
  The CVR registry is the authoritative source for Danish company data. Cached records may lag the live registry by up to the configured TTL period.
</Note>

## GET /api/cvr/participant — Fetch participant/director profile

Returns the full profile for a CVR participant (a person or legal entity registered as a director, owner, or board member), including all of their company affiliations and roles across the registry.

### Request

```
GET /api/cvr/participant
```

### Query parameters

<ParamField query="id" type="string" required>
  The CVR participant number (numeric, e.g. `4001234567`). Non-numeric values are rejected with a `400` error.
</ParamField>

<ParamField query="fromVat" type="string">
  The 8-digit VAT number of the company where this participant was first encountered. Providing this improves accuracy: if the CVR participant endpoint does not return company affiliations directly, the route falls back to extracting roles from the originating company's participant list.
</ParamField>

### Response

```json
{
  "participant": { ... }
}
```

<ResponseField name="participant" type="object">
  A `CvrParticipant` object — the raw participant data from CVR enriched with a normalised `companies` array.

  <Expandable title="participant fields">
    <ResponseField name="participantnumber" type="number">
      Unique CVR participant identifier.
    </ResponseField>
    <ResponseField name="slug" type="string">
      URL-friendly participant slug.
    </ResponseField>
    <ResponseField name="life.name" type="string">
      Full legal name of the participant.
    </ResponseField>
    <ResponseField name="life.profession" type="string | null">
      Stated profession.
    </ResponseField>
    <ResponseField name="life.deceased" type="boolean">
      Whether the participant is recorded as deceased in the CVR registry.
    </ResponseField>
    <ResponseField name="address" type="object">
      Participant address (street, zipcode, cityname, countrycode, freetext). May be absent if the participant has opted out of address publication (`unlisted: true`).
    </ResponseField>
    <ResponseField name="contact" type="object">
      Optional contact info (email, www, phone) when registered.
    </ResponseField>
    <ResponseField name="companies" type="array">
      Array of `CvrParticipation` objects representing every company this participant is or was affiliated with. Each entry includes:

      <Expandable title="CvrParticipation fields">
        <ResponseField name="vat" type="number">
          VAT number of the affiliated company.
        </ResponseField>
        <ResponseField name="slug" type="string">
          Company slug.
        </ResponseField>
        <ResponseField name="life.name" type="string">
          Company name.
        </ResponseField>
        <ResponseField name="life.start" type="string | null">
          Company founding date.
        </ResponseField>
        <ResponseField name="life.end" type="string | null">
          Dissolution date, or `null` if active.
        </ResponseField>
        <ResponseField name="companyform.description" type="string | null">
          Company type label.
        </ResponseField>
        <ResponseField name="companystatus.text" type="string | null">
          Company status (e.g. `NORMAL`, `OPLØST`).
        </ResponseField>
        <ResponseField name="roles" type="array">
          Array of roles held by this participant in the company. Each role has `type`, `life.start`, `life.end`, `life.title`, `life.owner_percent`, and `life.owner_voting_percent`.
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

### Error responses

| Status | Meaning |
|--------|---------|
| `400`  | Missing or non-numeric `id` parameter. |
| `404`  | Participant not found in the CVR registry. |
| `500`  | Upstream CVR API failure. |

## Example

```bash
# Fetch full company profile
curl "https://your-domain.com/api/cvr/company?vat=12345678"

# Fetch participant profile with originating company hint
curl "https://your-domain.com/api/cvr/participant?id=4001234567&fromVat=12345678"
```
